## Outcome

Concurrent requests preserve one active attempt and every valid collected signature.

## Start and handoffs

Build against the published AttemptStore interface and synthetic payment fixtures. Do not wait for P3/P4.

Implementation prerequisites: [B1](https://github.com/nefalos-tech/OneTab/issues/13)

## Work

- [ ] Implement reserve attempt, save frozen message, insert verified signature, claim submission, persist signed bytes/reference, and record observed result.
- [ ] Use database transactions, constraints and conditional transitions for concurrency. Do not rely on process-local locks.
- [ ] Keep each signature attached to its attempt and expected signer. Prevent last-write-wins replacement of the signature set.
- [ ] Reject mutation of a frozen message and prevent replacement attempts while a prior attempt is active or unresolved.
- [ ] Provide restart-safe reads and idempotent transitions. Allow the payment owner to persist signed bytes/reference before network submission.
- [ ] Keep database helpers independent of payment orchestration to prevent circular imports.

## Done when

- [ ] Concurrent prepare requests produce one active attempt.
- [ ] Concurrent signer uploads preserve both signatures.
- [ ] Only one submission claim wins and duplicate writes are harmless.
- [ ] Restarting the server preserves the attempt, message, signatures and transaction reference.
