## Outcome

Only expected, authenticated payers can contribute a valid signature to the current attempt.

## Start and handoffs

Build against the agreed AttemptStore fake while B4 implements real persistence.

Implementation prerequisites: [P2](https://github.com/nefalos-tech/OneTab/issues/2), [B1](https://github.com/nefalos-tech/OneTab/issues/13)

Needed for final integration: [B2](https://github.com/nefalos-tech/OneTab/issues/14), [B3](https://github.com/nefalos-tech/OneTab/issues/15), [B4](https://github.com/nefalos-tech/OneTab/issues/16), [F4](https://github.com/nefalos-tech/OneTab/issues/10).

## Work

- [ ] Allow the organizer to prepare an attempt after the room is full and everyone is Ready. Use AttemptStore to reserve exactly one active attempt.
- [ ] Store the immutable message, hash, participant snapshot and lifetime before exposing SigningPayload.
- [ ] Verify returned signatures against the expected wallet and exact stored message. Merge by signer slot without overwriting signatures from other requests.
- [ ] Make identical reuploads harmless. Reject stale attempt IDs, unexpected signers, mutated payloads and uploads after the attempt stops accepting signatures.
- [ ] Keep Ready separate from Signed. Wallet rejection stops collection but does not promise revocation of already-issued signatures.

## Done when

- [ ] Two concurrent signature uploads both persist.
- [ ] Missing, invalid, unexpected and stale signatures cannot advance the attempt.
- [ ] Duplicate preparation returns the existing attempt rather than a second one.
