Owner: @SophiaChua

Estimated effort: 3 hours. This is a planning budget, not a delivery guarantee.
Phase: Build

## Outcome

Every state-changing request is tied to a verified wallet, not a client-supplied address.

## Start and handoffs

Use test signatures and the agreed authentication interface while F2 builds wallet UI.

Implementation prerequisites: [B1](https://github.com/nefalos-tech/OneTab/issues/13)

## Work

- [ ] Issue a unique, expiring, one-time challenge bound to wallet, intended origin/domain and purpose.
- [ ] Verify the signature and consume the challenge atomically. Establish a short-lived server-validated session in a secure cookie.
- [ ] Reject replay, wrong origin, wrong wallet, expired challenge and unauthenticated mutations. Add same-origin/CSRF checks appropriate to the routes.
- [ ] Provide session lookup and sign-out behavior for F2, including wallet account switching.
- [ ] Export the session guard for room and payment routes. Do not treat wallet connection or Ready as payment authorization.
- [ ] Keep authentication signing distinct from transaction approval.

## Done when

- [ ] A forged wallet address or reused challenge cannot join, ready or prepare as another payer.
- [ ] Valid signatures establish the expected wallet session.
- [ ] Rejected login does not change room/payment state.
