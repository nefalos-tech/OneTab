# F3. Build checkout creation, sharing and open-slot joining

Live issue: [#9](https://github.com/nefalos-tech/OneTab/issues/9)

This is the repository copy of the implementation brief. The live issue and board own status and discussion. Update both copies when the task scope changes.

Before implementation, read the [architecture](../architecture.md), [shared contracts](../contracts.md) and [development guide](../development.md).

Owner: @Quantomz
Lane: Frontend
Estimated effort: 3 hours. This is a planning budget, not a delivery guarantee.
Phase: Build

## Outcome

An organizer creates a fixed checkout and friends join it through a shareable link.

## Start and handoffs

Build forms and room rendering using RoomSnapshot fixtures; wire real routes when available.

Implementation prerequisites: [F1](https://github.com/nefalos-tech/OneTab/issues/7)

Needed for final integration: [F2](https://github.com/nefalos-tech/OneTab/issues/8), [B3](https://github.com/nefalos-tech/OneTab/issues/15).

## Work

- [ ] Collect title, seller wallet, positive USDC total and two or three payers. Show a review step and exact shares before creating.
- [ ] Keep seller, total and participant count immutable once created. Explain that corrections require a new checkout.
- [ ] Treat the organizer as the first payer. Let distinct wallets with the link claim remaining slots.
- [ ] Show seller, total, all participant wallets, individual shares and the viewer's own contribution.
- [ ] Handle invalid input, duplicate wallet, full room, missing checkout, loading and request errors. Copy the share link.
- [ ] Read GET /api/config on the server for the create form. When it fails, keep "Checkouts can't be created right now" with words that fit a temporary outage. Added on 2026-11-07.
- [ ] Ask the organizer to connect and sign in at the review step, in place of Create checkout, and return to the form when the signed-in wallet is the seller. Added on 2026-11-07.
- [ ] Tell a seller who opens the room that they don't take a spot. Added on 2026-11-07.

Until B2, B3 and P1 land, the requests and the room ordering are proven by unit tests with a stubbed fetch, and the e2e suite reads live rooms from a fake API through `ONETAB_API_ORIGIN`. A live sign-in can't happen in a browser before P1, so the Done when evidence, a signed-in create, two joins, a full room and a reload on the hosted Devnet app, comes after those cards. Restoring a live sign-in on reload needs P1's silent reconnect.

## Done when

- [ ] An organizer and two friends can enter the same room using its link.
- [ ] The organizer counts toward the payer limit and no wallet claims two spots.
- [ ] Refresh preserves the room and its immutable payment details.
