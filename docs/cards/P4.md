## Outcome

Refreshes, concurrent requests and lost RPC responses cannot cause an automatic replacement payment.

## Start and handoffs

Implement and test with a fake AttemptStore and RPC adapter, then wire the real store.

Implementation prerequisites: [P3](https://github.com/nefalos-tech/OneTab/issues/3)

Needed for final integration: [B4](https://github.com/nefalos-tech/OneTab/issues/16).

## Work

- [ ] Verify all required signatures and claim submission atomically through AttemptStore.
- [ ] Persist the fully signed transaction bytes and their derivable transaction signature before calling the RPC.
- [ ] Submit and reconcile the same transaction. Confirmation requires the intended commitment and no execution error, not merely a returned transaction reference.
- [ ] Persist state so polling can resume after process or browser restart. Permit rebroadcasting identical signed bytes only while valid.
- [ ] Represent unresolved outcomes explicitly. Check chain status and block height before declaring expiration. Do not create a replacement while the original outcome is unresolved.
- [ ] Require fresh signatures for a fresh blockhash. Keep the distinction between transfer failure and network fees.

## Done when

- [ ] Concurrent submit calls use one attempt and one transaction identity.
- [ ] A dropped response after successful broadcast later resolves to the same receipt.
- [ ] A backend restart between persistence and send can resume without constructing another payment.
- [ ] Expiry requires a fresh attempt and fresh approvals.

## File ownership

Proposed: src/server/payments/submit.ts and reconcile.ts. B4 implements submission locking and durable storage.
