## Outcome

Participants see the confirmed result or an accurate explanation of what remains unresolved.

## Start and handoffs

Build pending, failed, expired, unresolved and confirmed views against fixtures before the real RPC flow is ready.

Implementation prerequisites: [F3](https://github.com/nefalos-tech/OneTab/issues/9), [F4](https://github.com/nefalos-tech/OneTab/issues/10)

Needed for final integration: [P4](https://github.com/nefalos-tech/OneTab/issues/4).

## Work

- [ ] Show pending, confirmed, failed, expired and unresolved as distinct states from the server.
- [ ] Render a receipt only for confirmed success. Include seller, total, payer shares, transaction reference and Devnet explorer link.
- [ ] Restore the existing attempt after reload. Continue checking the same transaction after connection loss.
- [ ] Allow restart only when the server says the prior attempt is safely resolved and fresh approvals are required.
- [ ] Explain insufficient USDC/SOL and rejected prompts with a next action. Do not display a misleading successful or canceled state.

## Done when

- [ ] Refreshing during signing or submission restores the same attempt.
- [ ] A transaction reference by itself never produces a success receipt.
- [ ] An unresolved outcome has no action that silently starts another payment.
