Estimated effort: 2 hours. This is a planning budget, not a delivery guarantee.
Phase: Verify and submit

## Outcome

The payment claims used in the demo are supported by recorded checks.

## Start and handoffs

Prepare the failure cases while submission is being implemented; run them when the integrated flow is ready.

Implementation prerequisites: [P4](https://github.com/nefalos-tech/OneTab/issues/4)

Needed for final integration: [F5](https://github.com/nefalos-tech/OneTab/issues/11), [B4](https://github.com/nefalos-tech/OneTab/issues/16).

## Work

- [ ] Exercise a missing signature, invalid signature, wallet rejection, insufficient USDC, insufficient fee SOL, and expired message.
- [ ] Exercise a stale signature upload, double prepare, double submit, refresh during submission, and a lost RPC response.
- [ ] Check balances and final state for each case. Include any network fee in the explanation.
- [ ] Label preflight rejection accurately. Claim blockchain rollback only if a controlled on-chain failing-transfer test actually proves it.
- [ ] Confirm there is no immediate cancellation claim and no replacement attempt while prior authorization remains unresolved.

## Done when

- [ ] Record each scenario, observed result and evidence in the payment failure report.
- [ ] Every failed or rejected purchase avoids a successful partial seller payment.
- [ ] Expiry/retry and timeout/recovery preserve the required transaction identity rules.
