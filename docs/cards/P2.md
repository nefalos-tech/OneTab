Estimated effort: 2 hours. This is a planning budget, not a delivery guarantee.
Phase: Build

## Outcome

The server and browser agree on exactly what each participant will authorize.

## Start and handoffs

Use the agreed contract and an in-memory store. Production persistence is not required to start.

Implementation prerequisites: [P1](https://github.com/nefalos-tech/OneTab/issues/1), [B1](https://github.com/nefalos-tech/OneTab/issues/13)

## Work

- [ ] Use integer token units and deterministic slot-based remainder allocation for two or three equal shares. JSON amounts are decimal strings.
- [ ] Validate Devnet, the configured USDC mint, source accounts and owners, seller destination, fee payer, allowed programs, signer set, and transfer amounts.
- [ ] Build one transfer per payer with a fresh blockhash and last valid block height. Freeze the exact message bytes and store their hash.
- [ ] Export the same payment-plan validator for F4 to run before any wallet signature request.
- [ ] Preflight balances and required token accounts. Give clear errors for insufficient USDC, missing token accounts, and insufficient organizer SOL.

## Done when

- [ ] Shares sum exactly to the total, including a non-divisible amount.
- [ ] Changing seller, amount, program, mint, fee payer or signer set fails validation.
- [ ] Two-payer and three-payer payloads decode to the expected complete payment plan.
