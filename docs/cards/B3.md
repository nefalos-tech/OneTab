Phase: Build

## Outcome

Separate browsers share a persistent room with correct participants and readiness.

## Start and handoffs

Implement the routes against the agreed fixtures and session guard; no Solana submission dependency.

Implementation prerequisites: [B1](https://github.com/nefalos-tech/OneTab/issues/13), [B2](https://github.com/nefalos-tech/OneTab/issues/14)

## Work

- [ ] Create a checkout with immutable seller, total, payer count, network and mint. Add the organizer in the first stable payer slot.
- [ ] Validate input at the server boundary and compute exact equal shares with the agreed deterministic remainder rule.
- [ ] Allow any authenticated distinct wallet holding the link to atomically claim an open slot. Rejoining an existing slot is idempotent.
- [ ] Persist readiness, return the agreed RoomSnapshot and support polling.
- [ ] Freeze the relevant participant/readiness snapshot when an attempt starts. Reject unauthorized or stale mutations.
- [ ] Return clear errors for full room, invalid checkout, duplicate request and session problems.

## Done when

- [ ] Concurrent join requests cannot overfill a two- or three-payer room.
- [ ] Only the current wallet changes its own readiness.
- [ ] Refresh preserves participants and exact shares.
- [ ] Seller, total and participant count cannot be edited after creation.
