## Outcome

Separate browsers share a persistent room with correct participants and readiness.

## Start and handoffs

Implement the routes against the agreed fixtures and session guard; no Solana submission dependency.

Implementation prerequisites: [B1](https://github.com/nefalos-tech/OneTab/issues/13), [B2](https://github.com/nefalos-tech/OneTab/issues/14)

## Work

- [x] Create a checkout with immutable seller, total, payer count, network and mint. Add the organizer in the first stable payer slot.
- [x] Validate input at the server boundary and compute exact equal shares with the agreed deterministic remainder rule.
- [x] Allow any authenticated distinct wallet holding the link to atomically claim an open slot. Rejoining an existing slot is idempotent.
- [x] Persist readiness, return the agreed RoomSnapshot and support polling.
- [x] Freeze the relevant participant/readiness snapshot when an attempt starts. Reject unauthorized or stale mutations.
- [x] Return clear errors for full room, invalid checkout, duplicate request and session problems.

## Done when

- [x] Concurrent join requests cannot overfill a two- or three-payer room. A PostgreSQL 16 race test produced one slot winner and one `ROOM_FULL` response.
- [x] Only the current wallet changes its own readiness.
- [x] Refresh preserves participants and exact shares through the persisted public snapshot.
- [x] Seller, total and participant count cannot be edited after creation.

Implementation adds service-only security-definer RPCs in `20261107020000_b3_rooms.sql`, a room service and route handlers. `npm run lint`, `npm run typecheck` and all unit tests passed locally. The B3 test runner applied B1 through B3 to disposable PostgreSQL 16. It checked idempotency, readiness, privileges, snapshots and concurrent slot claims. The app-wide `npm run check` stops because the committed design-system document is stale. See [B3 test instructions](../../tests/b3/README.md).
